# Exploratory validation baseline

Run `uv sync --locked --extra dev --extra neural`, then `uv run --extra dev --extra neural python scripts/validate_data.py` followed by `uv run --extra dev --extra neural python scripts/run_validation.py --lstm`. Requires the prepared workbook, the `dev` dependencies and the proposed configuration. Outputs in `reports/generated/validation/` include product/fold metrics, daily predictions, exclusions and run metadata. The validation runner intentionally does not run calibration or test folds. The older `retailmind backtest` command still uses future coverage for cohort selection and is not the benchmark runner.

## Target and protocol

The primary target is daily **gross recorded positive units** for included product codes and positive prices. Cancellation lines and negative quantities are excluded, but positive sales that are later cancelled remain included. Sales are not unconstrained demand, and the cancellation sensitivity experiment is retrospective; it must not be used as historical model input without an as-of policy. The code-filter review remains incomplete.

The proposed 100-product cohort is selected solely from observations through 2011-04-30. Two 28-day validation origins are evaluated. At each cutoff, the historical series runs from the first observed positive sale to the cutoff, filling absent dates as zero recorded units; this is a source-coverage assumption, not proof of in-stock availability. Forecast target dates beyond a product's recorded panel are marked missing, not forced to zero. Both models use the same cohort, cutoff, context, horizon and scored product/fold mask. LightGBM is retrained on available cohort history at each cutoff; seasonal naive repeats the previous week. Its last 180 training windows per product are a preliminary choice. LightGBM uses the last 28 target days before each cutoff for early stopping (patience 10 boosting rounds, maximum 100 rounds), not the held-out forecast period.

## Initial results

In the current sales-only exploratory validation, pooled MAE / WAPE were 42.93 units / 127.78% for seasonal naive, 48.14 / 143.27% for LightGBM, and 29.88 / 88.95% for LSTM. There were 100 products across two cutoffs, with 5,600 daily observations per model. The LSTM restored epoch 5 of 8 in the first fold and epoch 7 of 10 in the second. These are initial validation results, not final test scores or a winning model selection. Earlier LightGBM results used calendar features and a different training policy and are superseded; a covariate-enhanced comparison will be reported separately. These are exploratory validation results, not a final ranking or estimate of production performance. The dashboard had already exposed the entire historical dataset before the split was designed. Results may change after refining code classification, cancellation policy, product segments and model settings.

The run is CPU-only. It records model fit time and per-product warm inference time, excluding startup, input loading and metric computation; these timings have not been standardized across hardware or supplemented with peak memory. They cannot support a final latency comparison. GPU training and inference are subject to the user’s 2 GB VRAM maximum and must not run until that limit can be reliably enforced and measured.
